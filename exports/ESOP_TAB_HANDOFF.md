# Handoff: build an "ESOPs" tab in the MassCEO Policy Tracker

You are adding a tab to the **MassCEO Policy Tracker** that presents Massachusetts
ESOP data from DOL Form 5500 filings. All the data is pre-aggregated for you in a
single JSON file — you do not need a database, and you should not re-derive any
figure yourself.

## The data

**Fetch:**
`https://raw.githubusercontent.com/jromanul/MAesopdashboard/main/exports/ma_esop_export.json`

~58 KB, one file, no auth. Committed to the repo, so it can be fetched at build
time or vendored into the project — either is fine. It is regenerated by
`export_policy_tracker_json.py` in that repo whenever the underlying data is
refreshed, so re-fetching picks up new figures without any code change here.

Source of truth for these numbers is the live dashboard at
<https://maesopdashboard.streamlit.app> — this export was verified field-by-field
against it, so the two should never disagree. If they do, the dashboard is right
and this file is stale.

## The one thing you must get right

There are **two population bases**, and they are not interchangeable. Every block
in the JSON declares which one it uses in a `"basis"` field.

| basis | 2024 value | means | use it for |
|---|---|---|---|
| `active` | **119 plans** | reporting at least one active participant, minus known defunct/wind-down plans | "how many working MA ESOPs", every per-plan average, all industry views |
| `filed` | **133 plans** | every ESOP that filed for the year, including plans winding down | the year-over-year trend lines |

The trend series uses `filed` because a trend line has to count the same way in
every year, and earlier years cannot be re-adjudicated. Everything else uses
`active`. **Do not put 119 and 133 on the same chart**, and label any headline
figure with which one it is. If you show a single "number of MA ESOPs", use
**119** and call it *active* plans.

## What to build

One page, these sections in order. Titles are suggestions; the numbers are not.

### 1. Headline row — from `headline`

Five or six stat tiles:

- **119** Active MA ESOPs — `active_plans`
- **27,856** Participants — `total_participants`
- **$3.99B** Total assets — `total_assets`
- **$6.46M** Median plan size — `median_assets_per_plan`
- **$116,894** Median assets per active participant — `median_assets_per_active_participant_per_plan`
- **$143,158** Assets per participant (aggregate) — `aggregate_assets_per_participant`

The medians are the ones that describe a *typical* plan. Means are in the same
object (`mean_assets_per_plan` is **$33.5M**) but are pulled far above the typical
plan by a handful of very large ESOPs — Consigli alone is $729M. If you show only
one, show the median. If you show both, label them.

### 2. Typical plan profile — from `typical_plan.rows`

A five-row table, columns Metric / Median / Mean. Already ordered; `unit` on each
row is `years`, `people` or `usd` so you can format without parsing the label.

### 3. Trends over time — from `trends`

`trends.years` is the shared x-axis (2014–2024, 11 points). Each key in
`trends.series` is a parallel array of the same length. Suggested charts:

- Plan count — `plan_count`
- Participants — `total_participants` and `active_participants` as two lines
- Total assets — `total_assets`
- Contributions vs distributions — `employer_contributions` and `benefits_paid` as grouped bars

Note that 2024's participant series dip against 2023 (by 1,303 total and 2,207
active). Nearly all of the dip is at plans that filed in both years, chiefly a few
plans shrinking or winding down (Abt Global, Harpoon Brewery, both L.S. Starrett
plans); plans entering and leaving the dataset add participants on net. Do not
annotate it as a statewide decline in employee ownership.

### 4. Distributions — from `distributions`

Two histograms, `plan_assets` and `participant_counts`. Each is an ordered array
of `{label, count}`; both sum to 119. Render in array order — the labels are
ranges, so alphabetical or by-value sorting will scramble them.

### 5. Formation cohorts and decade shares — from `formation_cohorts`, `decade_shares`

`cohorts` gives plans, participants and assets per era (sums to 119). `decades`
gives plans and `pct_of_active` per decade. Each percentage is rounded to one
decimal, so after a data refresh the column can sum to 99.9% or 100.1%. Do not
"fix" this by normalising; if a total is displayed, either show 100% as a label
or sum the raw plan counts (119) instead.

### 6. Industry — from `industry.sectors`

Already sorted by plan count descending, which is the order to render. Each entry
has `sector`, `plans`, `participants`, `assets`, `avg_account_balance` and
`include_in_balance_table`.

- Sector bar chart — `plans` (all 11 sectors, sums to 119)
- Average account balance table — `avg_account_balance`, filtered to rows where
  `include_in_balance_table` is true (8 of the 11 sectors). A one-plan sector's
  "average" is just that plan and reads as a sector characteristic when it is
  not, so the flag is precomputed rather than left to you to remember.
- Share charts by plans / participants / assets — group the small sectors into an
  "Other" bucket yourself; `industry.totals` gives the denominators.

### 7. Optional: plan roster — from `plans`

All 119 active plans, sorted by assets descending, with sponsor, city, industry,
participants and assets. Useful for a sortable table or a "largest plans" list.
`employer_securities` is `null` for the six plans that left the line blank (see below).

## Labelling rules — these prevent published errors

Carry these into any tooltip, footnote or methodology blurb:

1. **Participants are year-end counts.** `total_participants` is the plan total
   at the *end* of the plan year (Form 5500 line 6f): current employees, retirees,
   former employees still owed a balance, and beneficiaries. `active_participants`
   is current employees on the same date (line 6a). `total_assets` and
   `employer_securities` are year-end balances; `employer_contributions` and
   `benefits_paid` are totals for the plan year. Label participants "at year end"
   wherever a date is shown. (If your cached export's `meta.generated_utc` is
   earlier than 2026-10-28, or its first caveat says "BEGINNING of the plan year",
   re-fetch it: earlier files used the start-of-year total, line 5.)

2. **`employer_securities`: null is not zero.** Company stock comes from Schedule H
   line 1d(1) for large plans and Schedule I line 3d for small plans. 112 of the
   119 active plans report a positive value; one reports $0 and six leave the line
   blank (`null`). Before the October 2026 refresh only Schedule H was read, so
   only 34 plans carried a figure — if you cached the old file, re-fetch it.

3. **The most recent form year is not final.** Plans may file up to 9½ months
   after a plan year ends (about 21½ months after it begins), so 2024 will keep
   growing. Show the "as of" date from
   `meta.data_as_of`.

4. **Form year 2025 is deliberately absent.** It is still open (`meta.open_form_year`)
   and its partial counts are not comparable to completed years.

5. **Attribute the source.** DOL EFAST2 Form 5500 bulk datasets; `meta.source_url`.
